1. Abstract

Small drones are difficult visual targets because they occupy few pixels, move rapidly relative to their apparent size, and cross backgrounds that range from clear sky to foliage and buildings. This project implements and validates an honest electro-optical/infrared (EO/IR) research pipeline that accepts a real video, detects drones with a fine-tuned YOLOv8s model, associates detections with a custom ByteTrack-style tracker, estimates pixel-space position and velocity with a per-track linear Kalman filter, and exports an annotated video plus a structured JSON record.

The detector was trained on the DUT Anti-UAV detection dataset after conversion from Pascal VOC XML to normalized YOLO horizontal bounding-box labels. The measured validation results are precision 0.956, recall 0.868, mAP@0.50 of 0.907 and mAP@0.50:0.95 of 0.577. These values are detector validation metrics; they are not multi-object tracking metrics and are not presented as field performance.

A real test exposed an identity-continuity failure: the drone disappeared for 125 frames while the low-level tracker retained a lost track for only 90 frames. The returning drone therefore created a second immutable internal track. The implemented correction adds a separate operator-facing identity layer. A returning track first receives a visible temporary identifier, such as TEMP-1, while eight frames of motion, appearance, box-size and elapsed-time evidence are collected. The resolver then restores an acceptable dormant identity or promotes the temporary identity to a new permanent identifier.

On the approved 373-frame test video, the resolver preserved two internal tracker histories but produced one confirmed operator identity. TEMP-1 was displayed on frames 169-175 and restored to ID-1 on frame 176 with a hybrid match cost of 0.2404 and appearance similarity of 0.9953. The post-merge run processed the video at 47.2 FPS on an NVIDIA RTX 2000 Ada GPU. This is a single measured run, not a universal throughput guarantee.

2. Introduction

2.1 The Big Picture and Operational Context

Low-cost unmanned aerial systems can produce consequences that are disproportionate to their purchase price and physical size. The December 2018 Gatwick Airport disruption affected approximately 140,000 passengers and more than 1,000 flights. Published economic estimates vary according to whether airport, airline, passenger and wider industry effects are counted; a peer-reviewed case estimate placed the wider 33-hour loss at approximately EUR 55.8 million. The defensible lesson is not one exact monetary value, but the operational leverage of a small aerial intrusion against critical infrastructure.

Visual detection is only one part of the challenge. An operator also needs continuity: the system must explain whether a current observation belongs to a known drone, a temporarily lost drone, or a genuinely new object. A tracker that assigns a new identifier after a long disappearance is behaving consistently with finite memory, yet the resulting identity change can confuse an operator. This project therefore separates the immutable engineering track history from the logical identity presented to the user.

2.2 Project Objectives

  1. Fine-tune a real drone detector using the annotations actually supplied by the selected dataset.
  2. Process user-supplied videos and produce repeatable annotated-video and JSON outputs.
  3. Maintain short-gap track continuity through motion-predicted association and lost-track revival.
  4. Estimate smoothed pixel position, velocity and uncertainty with a linear Kalman filter bank.
  5. Resolve long-gap identity interruptions without rewriting low-level track identifiers.
  6. Expose the real EO/IR result in a professional dashboard while marking unavailable capabilities clearly.
  7. Provide an educational SAPIENT-inspired JSON structure without claiming Protobuf wire compatibility or certification.

3. Background and Literature Review

3.1 Drone Detection and Bounding-Box Choice

YOLO-family detectors provide a practical balance between localization accuracy and inference speed. The present model uses Ultralytics YOLOv8s and one learned class, drone. The project adapter converts detector output from corner coordinates into a shared center-size representation:

cx = (x1 + x2) / 2;   cy = (y1 + y2) / 2;   w = x2 - x1;   h = y2 - y1

The codebase contains a field named angle in the common box representation, but the dataset labels are axis aligned and the runtime adapter sets the angle to zero. This does not make the detector an oriented-bounding-box model.

Why the data were not converted to OBB

The DUT Anti-UAV detection annotations provide xmin, ymin, xmax and ymax. Genuine OBB training requires an observed orientation angle or four consistently ordered corner points. An automatic conversion could only set every angle to zero or invent an orientation from image appearance. Neither operation creates ground truth. Training or validating OBB on such pseudo-labels would therefore make the experiment difficult to defend scientifically.

Decision: use horizontal bounding boxes because they match the actual annotations. True OBB remains valid future work only after acquiring or manually producing genuine oriented labels.

3.2 Multi-Object Tracking and Kalman Estimation

ByteTrack demonstrated that associating lower-confidence detections in a second stage can improve track continuity. This repository contains a simplified, custom ByteTrack-style implementation rather than the official package. The active matching path predicts a center from recent motion, constructs a box-size-scaled search radius, and selects the nearest valid detection. Tracks move through tracked, lost and removed lifecycle states. A high-confidence detection can revive a lost track while it remains inside the configured memory limit.

A separate linear Kalman filter bank estimates a state vector x = [px, py, vx, vy]^T from center measurements z = [px, py]^T. The standard prediction and correction equations are:

x- = F x    |    P- = F P F^T + Q
K = P- H^T (H P- H^T + R)^-1    |    x = x- + K(z - Hx-)

The tracker lifecycle and Kalman-filter cleanup windows are separate. The Kalman output is an estimator of image-plane state; without camera calibration it must not be described as physical range, altitude or speed in metres per second.

3.3 Identity Reconciliation and Re-Identification

Short-term tracking and long-gap identity are different problems. A low-level tracker needs finite memory so stale tracks do not accumulate indefinitely. An operator-facing system, however, may retain a richer dormant record and compare a new track with prior identities. The new resolver stores the permanent identity, last Kalman state, center, box size, velocity, appearance descriptor, internal track history and last-seen time.

The current appearance descriptor is a compact normalized hue/saturation and brightness histogram extracted from the real crop. It is supporting evidence, not a trained deep ReID embedding. The temporal-model protocol is an extension point for a future trained LSTM, but no random or untrained LSTM is enabled because untrained weights would generate meaningless identity scores.

3.4 SAPIENT Interoperability Context

SAPIENT is specified by BSI Flex 335 and adopted by NATO under STANREC 4869. The real interface uses Protocol Buffers v3, registration and acknowledgement flows, defined message types and real coordinate systems. This repository emits readable JSON shaped around selected DetectionReport and StatusReport concepts. Pixel locations are explicitly marked as image coordinates. The implementation is educational and structurally useful, but it is not wire compatible, certified or a substitute for a conformance-tested SAPIENT node.

4. Proposed Methodology

Input MP4 -> YOLOv8 detection -> custom track association -> Kalman state -> identity resolver -> annotated MP4 + JSON -> dashboard export

4.1 YOLOv8 Detection Engine

The main entry point loads models/best.pt, decodes the source video with OpenCV, and invokes Ultralytics once per frame. Detections below the configurable confidence threshold are removed. The demonstrated command uses confidence 0.25, image size 640 and GPU device 0. Each retained box contains center, width, height, confidence, class and an angle fixed to zero because the model is horizontal-box based.

4.2 Custom ByteTrack-Style Tracker

For each frame, the tracker predicts track centers and associates detections using distance within a scale-aware radius. Unmatched active tracks become lost. A lost track can be revived with the same internal ID until max_time_lost is exceeded; after expiry, a later detection receives a new internal ID. Internal IDs are never rewritten because they document the actual lifecycle of the low-level tracker.

The approved test used the default 90-frame lost-track window. The drone was detected through frame 43, absent during frames 44-168, and returned at frame 169. Because the 125-frame interruption exceeded the tracker memory, internal track 1 expired and internal track 2 was correctly created.

4.3 Kalman Filter and Hybrid Identity Resolver

The identity resolver operates above the tracker. When a confirmed identity disappears, its record becomes dormant for 10 seconds by default. If a new internal track appears while a dormant candidate exists, the system immediately displays a temporary identity and begins multi-frame comparison. Detection is never delayed while identity is uncertain.

The current hybrid cost is:

C = 0.35 d_motion + 0.35 d_appearance + 0.15 d_size + 0.15 d_time
  • d_motion: distance from the short-term predicted position normalized by size, time gap, velocity and uncertainty.
  • d_appearance: cosine distance between the dormant and new crop descriptors.
  • d_size: logarithmic change in bounding-box diagonal.
  • d_time: the consumed fraction of the dormant retention window.

A candidate must satisfy the cost threshold, minimum appearance gate and ambiguity margin after the configured eight evidence frames. A valid match restores the old permanent identity. If no acceptable match is available after 24 provisional frames, the temporary identity becomes a new permanent identity. An abandoned or end-of-video temporary identity remains explicitly auditable instead of being silently fabricated into a match.

4.4 Output Contract, SAPIENT-Inspired JSON and Dashboard

Every frame record includes detections, enriched tracks, Kalman states, identity events and a SAPIENT-inspired detection batch. The track object preserves both the immutable internal_track_id and the operator-facing display_id. For finite-video post-processing, display_id_at_frame retains what the operator saw at that moment while final_display_id records the resolved alias.

The dashboard is a static HTML/CSS/JavaScript application. The conversion utility produces a browser feed from real pipeline JSON. Capabilities are explicit: when radar, RF, acoustic, multi-sensor fusion, georeferencing or effectors are unavailable, the interface must show them as unavailable rather than animating fabricated operational data.

5.2 Detection Metrics

Precision = TP / (TP + FP)     Recall = TP / (TP + FN)

Average Precision integrates the precision-recall curve for a class at a specified intersection-over-union threshold. mAP@0.50 evaluates at IoU 0.50, while mAP@0.50:0.95 averages over thresholds 0.50 to 0.95 in steps of 0.05. The latter is stricter because localization quality matters increasingly at high IoU thresholds.

5.3 Why MOTA Was Not Reported

MOTA = 1 - sum_t(FN_t + FP_t + IDSW_t) / sum_t(GT_t)

Multiple Object Tracking Accuracy requires a tracking ground truth that assigns persistent identities to every object across frames. The selected detector dataset supplies boxes but does not provide the project with a verified evaluation set containing consistent track identities, occlusion states, entries and exits. The user-supplied demonstration video also has no independent frame-by-frame identity annotation. Computing MOTA from the system's predictions alone would compare the output with itself and would not be valid.

MOTA is also detection dominated: false positives and false negatives can obscure identity quality. When a labelled tracking set is created, the project should report MOTA together with IDF1, HOTA, identity-switch count, re-identification precision and re-identification recall.

6.3 Software Verification and Deployment Readiness

The merged feature is covered by tests for immediate new identity creation, temporary-to-old-ID restoration, different-appearance promotion, retention expiry, abandoned temporary tracks, SAPIENT object identity selection, low-level tracker lifecycle and Kalman lifecycle. The post-merge suite completed 10 Python tests successfully, and the dashboard contract completed nine capability assertions.

The deployment runbook separates the offline Python processing stage from the static browser dashboard. It documents virtual-environment setup, platform-specific PyTorch installation, environment verification, CPU/GPU execution, dashboard export and local static serving. The input videos and generated results remain local and are excluded from routine source-control updates.

6.4 Limitations and Failure Modes

  • The detector has one class and does not identify drone make, model or payload.
  • Horizontal boxes can include extra background for rotated targets.
  • The custom tracker is simpler than a production multi-object tracker and has not been benchmarked on a labelled MOT suite.
  • Histogram appearance is weak when drones occupy very few pixels or look similar.
  • A long disappearance increases motion uncertainty and false-revival risk.
  • The current identity thresholds were demonstrated on a limited set and require calibration on labelled positive and negative re-entry cases.
  • No trained LSTM or deep ReID network is enabled.
  • All locations and velocities are image-plane values.
  • SAPIENT output is a JSON approximation, not a certified interface.
  • Radar, RF, acoustic fusion and effectors are not operational components.

6.5 Economic Relevance Without Fabricated ROI

The project demonstrates a reproducible visual baseline relevant to monitoring critical infrastructure. It does not provide evidence for a specific return on investment, cost reduction percentage or countermeasure effectiveness. A future business case would require field false-alarm rates, staffing requirements, equipment cost, maintenance, regulatory obligations, integration cost and quantified avoided-loss scenarios.

7. Conclusion and Future Work

7.1 Key Technical Takeaways

  1. The YOLOv8s detector is trained and measured on the selected real dataset.
  2. Horizontal boxes are the correct scientific choice for the supplied annotations.
  3. The low-level tracker and Kalman filter provide real per-frame continuity and pixel-state estimation.
  4. The identity resolver fixes the demonstrated long-gap operator-ID problem without corrupting internal track history.
  5. Temporary identities make uncertainty visible instead of pretending the decision is immediate.
  6. The dashboard and documentation expose unavailable capabilities instead of presenting simulation as operational evidence.

7.2 Prioritized Roadmap

  1. Create an identity-labelled multi-video evaluation set with re-entry and hard-negative cases.
  2. Measure MOTA, IDF1, HOTA, identity switches and re-identification precision/recall.
  3. Calibrate identity thresholds by frame rate, camera type and target scale.
  4. Train and validate a temporal LSTM only when sufficient identity-labelled trajectories exist.
  5. Evaluate a learned appearance embedding against the histogram baseline.
  6. Acquire genuine oriented labels before testing a true OBB model.
  7. Add camera calibration and georeferencing for physical coordinates.
  8. Integrate real radar/RF/acoustic devices before claiming multi-sensor performance.
  9. Implement Protobuf SAPIENT messages and conformance testing.
  10. Conduct operator-centred usability and safety evaluation.
