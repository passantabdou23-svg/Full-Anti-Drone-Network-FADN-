# Deployment runbook

This repository has two separate runtime stages:

1. A Python process runs YOLO detection, tracking, and Kalman estimation on a
   video and writes JSON plus an optional annotated video.
2. A static browser dashboard reads a converted JSON feed. The browser does
   not run YOLO and is not a live sensor or effector controller.

## 1. Create an isolated environment

From the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

On macOS or Linux, activate with `source .venv/bin/activate`.

Install PyTorch first. Use the command generated by the official selector at
<https://pytorch.org/get-started/locally/> so its CPU or CUDA build matches the
deployment host. A CPU-only starting point is:

```powershell
python -m pip install torch torchvision
```

Then install the direct project dependencies and verify the runtime:

```powershell
python -m pip install -r requirements.txt
python check_environment.py
```

On a headless Linux server that cannot load desktop OpenCV libraries, use the
official `ultralytics-opencv-headless` package instead of the desktop
`ultralytics`/`opencv-python` installation. The `--show` option is unavailable
in that configuration.

## 2. Run regression tests

```powershell
python -m unittest discover -s tests -v
```

If Node.js is available, also run the dashboard contract checks:

```powershell
node --check app.js
node tests\dashboard_smoke_test.js
```

Do not deploy when the environment check or regression suite fails.

## 3. Process a real video

GPU example:

```powershell
python detect_and_track_video.py `
  --video ".\input.mp4" `
  --weights ".\models\best.pt" `
  --out ".\video_results" `
  --device 0
```

For CPU deployment, replace `--device 0` with `--device cpu`. The expected
outputs are:

- `video_results/annotated_video.mp4`
- `video_results/detections_tracks.json`

Identity reconciliation is enabled by default. A returning drone first receives
an orange `TEMP-n VERIFYING` label. After the configured evidence window it is
either restored to a dormant `ID-n` (cyan `RECOVERED`) or promoted to a new
permanent ID. The defaults are:

```text
--identity_retention_seconds 10
--identity_confirm_frames 8
--identity_max_provisional_frames 24
--identity_match_threshold 0.62
```

At 24 FPS, 8 confirmation frames are about 0.33 seconds and 24 provisional
frames are about 1 second. These options are frame-rate aware except for the two
explicit frame counts. Keep the defaults for the demonstrated test path; tune
them only against labelled validation videos. Use `--disable_identity_resolver`
only for a controlled comparison with raw tracker IDs.

Before deployment, inspect `identity_summary` in `detections_tracks.json` and
confirm that:

- `confirmed_identity_count` is plausible for the video.
- `identity_aliases` contains each resolved `TEMP-n` mapping.
- `event_counts.identity_reidentified` matches the recovered identities.
- unresolved temporary identities are investigated instead of silently treated
  as confirmed.

The detailed contract and measured test are in
[IDENTITY_RECONCILIATION.md](IDENTITY_RECONCILIATION.md).

## 4. Build the browser feed

```powershell
python export_for_dashboard.py `
  --input ".\video_results\detections_tracks.json" `
  --out ".\simulation_feed.json"
```

The historical filename `simulation_feed.json` is retained for frontend
compatibility. Its metadata now identifies whether its contents are real
EO/IR output or simulation. A real export explicitly disables radar, RF,
acoustic, multi-sensor fusion, georeferencing, and effector controls.

## 5. Serve and verify the dashboard

For local verification, bind the static server to the local machine only:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Open <http://127.0.0.1:8000/> and confirm:

- Data mode reads `REAL EO/IR OUTPUT` for a real export.
- Sensor mode reads `EO/IR ONLY`.
- Radar and multi-sensor buttons are disabled.
- Radar, RF, and acoustic panels state that no data is available.
- Effector buttons are disabled.
- Range displays `N/A` without georeferencing.
- The browser console contains no errors.

For a hosted static deployment, publish `index.html`, `styles.css`, `app.js`,
and the generated `simulation_feed.json` together through the chosen static
web server. Do not publish raw input videos, model weights, training datasets,
or the full `detections_tracks.json` unless they are intentionally required.

## Capability boundary

The real pipeline currently provides single-sensor EO/IR detections, tracking,
and pixel-space Kalman state estimation. SAPIENT output is an educational JSON
approximation, not wire-compatible Protobuf. Radar, RF, acoustic input,
multi-sensor fusion, georeferencing, and effector control remain unavailable
in the real deployment.
